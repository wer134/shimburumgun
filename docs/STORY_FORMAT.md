# 스토리 JSON 작성법

스토리 텍스트는 Java 코드에 들어가지 않는다. `src/main/resources/story/` 아래 JSON만 고치면 된다. 엔진을 건드릴 일은 없다.

```
src/main/resources/story/
  index.json      어떤 파일을 읽을지, 어디서 시작할지
  flags.json      쓸 수 있는 플래그·카운터 목록 (선언되지 않은 이름은 로딩 실패)
  prologue.json   스토리렛들
  chapter1.json
```

고친 뒤에는 반드시 검증을 돌린다. **오타는 플레이가 아니라 여기서 잡는다.**

```bash
gradle run --args="--validate"
```

---

## 스토리렛

이야기의 최소 단위다. 텍스트 한 덩어리와 선택지를 묶은 것.

```json
{
  "id": "ch1_03_name",
  "chapter": 1,
  "speaker": "윤동옥",
  "text": [
    "첫 문단.",
    "둘째 문단."
  ],
  "choices": [
    { "id": "ask", "text": "\"이름이 무엇이오.\"", "goto": "ch1_03b" }
  ]
}
```

| 항목 | 필수 | 설명 |
|------|:---:|------|
| `id` | ✓ | 전역 유일. 중복이면 로딩 실패 |
| `text` | | 문자열 또는 문자열 배열. 배열의 각 항목이 한 문단 |
| `speaker` | | 화자 이름. 없으면 지문으로 출력 |
| `chapter` | | 소속 장. 0은 프롤로그/막간 |
| `scene` | | `narrative`(기본) / `battle` / `shop` |
| `requires` | | 등장 조건. 없으면 항상 등장 가능 |
| `priority` | | 조건 선택에서 경합할 때 큰 값이 이김. 기본 0 |
| `once` | | `false`면 여러 번 등장 가능. 기본 `true` |
| `onEnter` | | 진입 즉시 적용할 효과 |
| `choices` | | 선택지 목록 |
| `next` | | 선택지가 없을 때 갈 곳. `choices`와 동시 사용 불가 |
| `ending` | | 엔딩이면 코드(`"A"`, `"B"`, `"C"`, `"HIDDEN"`) |

`_comment` 키는 어디에나 넣을 수 있고 무시된다.

---

## 다음 장면으로 넘기는 두 가지 방법

### 1. 명시 이동 — `goto` / `next`

선형 구간에 쓴다. 어디로 갈지 확정돼 있을 때.

```json
{ "id": "c1", "text": "받는다", "goto": "ch1_01_bamboo" }
```

### 2. 조건 선택 — 목적지를 비워 둔다

`goto`나 `next`를 **적지 않으면** 엔진이 고른다. 지금 상태에서 `requires`를 만족하고 아직 안 본 스토리렛 중 `priority`가 가장 높은 것이다.

```json
{ "id": "dig", "text": "주검을 찾아준다", "effects": [ { "flag": "원혼_소원_들어줌" } ] }
```

그러면 아래 둘 중 조건이 맞는 쪽이 자동으로 이어진다.

```json
{ "id": "ch1_05_mercy", "requires": { "flag": "원혼_소원_들어줌" }, "priority": 10, ... }
{ "id": "ch1_05_cold",  "requires": { "flag": "원혼_소원_들어줌", "is": false }, "priority": 10, ... }
```

**이 방식이 이 엔진의 핵심이다.** 같은 자리에 변주를 여러 개 두고 상태에 따라 갈아 끼울 수 있으므로, 장면을 추가할 때 기존 분기표를 고칠 필요가 없다. 새 JSON에 조건과 우선순위만 적어 넣으면 그 자리에 끼어든다.

---

## 조건 (`requires`)

```json
{ "flag": "원혼_이름을_물음" }                  플래그가 서 있으면
{ "flag": "원혼_이름을_물음", "is": false }     플래그가 없으면
{ "stat": "karma", "gte": 70 }                 공덕 70 이상
{ "counter": "혼_태운_횟수", "gte": 3 }         카운터 3 이상
{ "not": { "flag": "시험_거짓말" } }            부정
{ "all": [ ... ] }                             전부 참
{ "any": [ ... ] }                             하나라도 참
```

- 스탯: `karma` 공덕 / `soul` 혼력 / `hp` 체력 / `weapon` 낫 단계 / `han` 한
- 비교: `eq` `ne` `gt` `gte` `lt` `lte` — 하나만 쓸 것

히든 엔딩 조건(GDD 9장)을 그대로 옮기면 이렇게 된다.

```json
{ "all": [
    { "stat": "weapon", "gte": 5 },
    { "flag": "강림_제안_수락" }
] }
```

## 효과 (`effects` / `onEnter`)

```json
[
  { "karma": 15 },                             공덕 +15 (음수 가능)
  { "soul": -30 },                             혼력 -30
  { "hp": -12 },
  { "weapon": 1 },
  { "han": 1 },
  { "flag": "원혼_소원_들어줌" },                플래그 세움
  { "flag": "시험_거짓말", "set": false },       플래그 내림
  { "counter": "천도_횟수", "add": 1 }
]
```

수치는 자동으로 범위에 맞게 잘린다(공덕 0~100, 체력 0~100, 낫 +0~+5). 크게 적어도 게임이 깨지지 않는다.

---

## 검증기가 잡아주는 것

`gradle run --args="--validate"`는 오류를 **한꺼번에** 보고한다. 하나 고치고 다시 돌리는 일을 반복하지 않아도 된다.

- 스토리렛 `id` 중복
- 끊어진 `goto` / `next`
- `flags.json`에 없는 플래그·카운터 이름 (오타 방지)
- 어디서도 닿을 수 없는 스토리렛
- `choices`와 `next` 동시 사용
- 조건·효과의 문법 오류 (어느 파일 어느 스토리렛 몇 번째 선택지인지 짚어준다)

잡지 못하는 것도 있다. **모든 선택지가 조건부인 스토리렛**은 런타임에 걸린다 — 상태에 따라 선택지가 하나도 안 보일 수 있기 때문이다. 조건 없는 선택지를 하나는 남겨 둘 것.

## 새 장을 추가할 때

1. `src/main/resources/story/chapter2.json`을 만들고 `{"storylets": [...]}` 형태로 쓴다
2. `index.json`의 `files`에 파일명을 추가한다
3. 새 플래그를 쓸 거면 `flags.json`에 먼저 선언한다
4. `gradle run --args="--validate"`
5. `gradle run --args="--auto"`로 항상 첫 선택지를 고르는 스모크 플레이를 돌린다
